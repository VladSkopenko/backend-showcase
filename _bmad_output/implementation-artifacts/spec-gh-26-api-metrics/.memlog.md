- (direction) Spec folder lives in implementation-artifacts, not the default specs/, per .claude/rules/workflow.md; slug gh-26-api-metrics.
- (note) Source: hand-made draft stories.yaml and stories/1-api-request-metrics-on-a-private-port.md (bmad-build template) in this folder, made before this skill ran; stories.yaml is re-derived here, the story 1 file stays as story 1's spec.
- (decision) Three pull requests, decided by Vlad 2026-11-18: API metrics endpoint; Prometheus scraping dev; public Grafana API dashboard.
- (decision) Route label from an explicit table built in create_app from the (router, prefix) list with prometheus-client, not FastAPI native OpenTelemetry (Vlad, option a, 2026-11-18); reason: FastAPI 0.162 scope route lacks the include prefix, verified by probe.
- (capability) CAP-1 intent: Prometheus can read the API's request count, status and latency per full route template from a port the public host never serves. success: metrics port serves http_requests_total{method,route,status} and http_request_duration_seconds{method,route}; /metrics on the public dev host is 404.
- (capability) CAP-2 intent: a Prometheus in the platform stack collects dev API metrics labelled env=dev, its UI reachable only over the tailnet. success: Prometheus UI over the tailnet shows target api up with env=dev; public hosts do not serve it.
- (capability) CAP-3 intent: an anonymous visitor of the public Grafana sees the dev API's live request rate, 5xx share, latency and statuses. success: dashboard api on the public Grafana shows dev data; latency panels leave out /health and both SSE routes.
- (constraint) Metrics port (default 9000, METRICS_PORT) is never proxied by Caddy; port 8000 gains no /metrics (ADR 7, AD-13). Port 9000 is also reachable over edge, so the boundary is Caddy, recorded in ADR 21, amending the spine Metrics convention.
- (constraint) Labels bounded to method, route, status; route is the full template or unmatched; no ids, raw paths, query strings or personal data in any series.
- (constraint) env label comes from the Prometheus scrape config, not the app, so one image is promoted by digest across environments (AD-7 convention).
- (constraint) Apps never depend on the platform (AD-14): the API starts and serves when nothing scrapes it, and a dev deploy works with the platform down.
- (constraint) Anonymous Grafana Viewers can send any PromQL through the data source proxy (as SQL in ADR 19): Prometheus holds API counters only, and query timeout and max samples are lowered; recorded in ADR 21.
- (constraint) Platform services follow issue #26 shape and deploy from main through delivery.yml: init data dir, mem_limit, healthcheck, read-only config from the repo, tailnet UI via serve.json; no new secrets.
- (constraint) Infrastructure files are written one file per step with Vlad, every key checked in the official docs, local dry run first.
- (decision) Non-goals: node, postgres and redis exporters; Alertmanager, rules and the n8n probe; staging and prod targets (not live); OpenTelemetry and traces; process and platform collectors; Prometheus on a public host.
- (note) Review gotchas of 2026-11-18 for stories 2 and 3 go to companion gotchas.md (load-bearing), not invoke_dev_with.
- (constraint) Fixed values: Prometheus 3.15.x (spine), UI on tailnet port 9090, scrape app-dev-api:9000 every 15 s over internal network observability (API alias app-<env>-api), Grafana data source uid prometheus, not default.
- (decision) CAP-3 panels: requests per second by route, 5xx share, p50/p95 latency by route, responses by status, env variable.
