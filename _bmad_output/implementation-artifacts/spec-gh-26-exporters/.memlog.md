- (note) Project has no Redis, so the exporters are node_exporter and postgres_exporter only (AD-13 lists postgres_exporter and redis_exporter per app project).
- (capability) CAP-1 intent: Prometheus collects the VM's CPU, memory, load, disk and network, including free space on the shared /srv/data volume. success: Prometheus over the tailnet shows target node up; free bytes of / and /srv/data are queryable.
- (capability) CAP-2 intent: Prometheus collects dev PostgreSQL's connections, database size, transaction rate, cache hit ratio and locks, labelled env=dev. success: Prometheus shows target postgres up with env=dev; pg_up is 1 and the database size of app is queryable.
- (capability) CAP-3 intent: an anonymous visitor of the public Grafana sees the server's and dev database's health on a dashboard next to api. success: dashboard server on the public Grafana shows host CPU, memory, disk free of / and /srv/data, network, and dev Postgres connections, size, transactions per second and cache hit ratio.
- (capability) CAP-4 intent: the roadmap, README and issue #26 say observability ends after logs. success: issue #26 has Grafana and Prometheus steps ticked, Tempo and Alertmanager steps marked dropped; docs/roadmap.md Phase 4 and README What is next no longer promise traces or Telegram alerts.
- (constraint) node_exporter runs in the platform stack (one host), postgres_exporter inside the app stack (AD-13) in the one app compose file, so every environment runs one; Prometheus scrapes dev only (staging and prod not live).
- (constraint) Exporters join observability only; never edge; no published ports; Caddy unchanged; the postgres exporter is reached by alias app-<env>-postgres-exporter.
- (constraint) env label comes from the scrape config, as for the API (ADR 22); the node target carries no env (one host).
- (constraint) Apps never depend on the platform (AD-14): the app stack deploys with the platform down; a failing postgres_exporter never blocks the API.
- (constraint) Anonymous Viewers can query every stored series (ADR 22): node_exporter runs only the collectors the dashboard needs and none that name software versions, users or processes; postgres_exporter exposes no query text; series stay under the existing query limits.
- (constraint) Infrastructure files are written one per step with Vlad, every key checked in the official docs with a link, local dry run in throwaway containers first.
- (constraint) Platform service shape per issue #26: pinned image, mem_limit, healthcheck, read-only config from the repo; new Prometheus jobs go into deploy/platform/prometheus/prometheus.yml, reloaded by deploy.sh.
- (decision) Non-goals: Redis, cAdvisor or per-container metrics, staging and prod targets, alert rules, Tempo, Alertmanager, process collectors in the API, Postgres query statistics (pg_stat_statements).
- (question) Which database role postgres_exporter uses on dev: the app owner from POSTGRES_PASSWORD (no new secret, full rights) or a pg_monitor role from a migration with a SCRAM verifier like grafana_reader (least privilege, one new secret).
